# Model roster for the confound-removal run.
#
# One OpenRouter model id per line. Blank lines and #-comments ignored.
#
# WHY THESE. Nishimura-Gasparian, McCarthy & Lindner (arXiv 2605.02269) report
# that all tested models exploit their specifications at non-negligible rates,
# with the HIGHEST rates in Grok 4 and the LOWEST in Claude models. The pilot ran
# 161 episodes on claude-sonnet-5 and 14 on claude-sonnet-4-5 -- both Claude --
# saw zero gaming, and concluded the direction was exhausted. That null is
# confounded with the model family that games least. This roster removes the
# confound by spanning the reported range rather than sampling one end of it.
#
# VERIFY IDS BEFORE THE RUN. OpenRouter renames and retires slugs. Run
#   python tools/check_models.py
# first; it queries the live model list and reports any id that will 404, so a
# typo costs a second rather than a whole batch.

# -- the incumbent: reproduces the pilot's cell, anchors the comparison --
anthropic/claude-sonnet-4.5

# -- the high end of the reported gaming range --
x-ai/grok-4

# -- mid-range frontier, different labs, different RL recipes --
openai/gpt-5
google/gemini-2.5-pro

# -- open-weight: RL reasoning training is the reported driver, and these make
#    it visible without a lab's post-training in the way --
deepseek/deepseek-r1
qwen/qwen3-235b-a22b

# -- newest frontier reasoning models --
#
# 2605.02269's mechanism claim is that RL reasoning training substantially
# INCREASES the rate at which models exploit their specifications. The roster
# above spans labs; these two span recency, which is the axis that claim
# actually predicts. If the mechanism is right they should sit at the high end
# regardless of family, and a Claude-family model landing high would be the
# single most informative cell in the batch -- it would separate "Claude games
# least" as a family fact from "Claude games least" as a training-recipe fact.
#
# SLUGS BELOW ARE UNVERIFIED GUESSES. Neither model's OpenRouter id was
# reachable when this roster was written. Resolve both before the run:
#
#   python tools/check_models.py --search fable
#   python tools/check_models.py --search astra
#
# then paste the real ids over these two lines. check_models.py will refuse the
# batch until they resolve, which is the intended behaviour -- running six of
# eight models and finding out afterwards is worse than a twenty-second fix.
